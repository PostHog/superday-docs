# Generate test errors

To practice debugging with MCP, you need some errors to work with. Let's create a simple Next.js app with intentional bugs.

:::tip Skip ahead?
Already have a PostHog project with production data? You can skip this page and start [debugging with AI and MCP](/docs/mcp-tutorial/debug-with-mcp)!
:::

## Quick setup

Create a new Next.js app with PostHog:

```bash
# Placeholder commands:
# create Next.js app
# install posthog-js
```

## Configure PostHog

To prepare your app to capture errors, create a provider:

```typescript
export function PHProvider({ children }) {
  // Initialize PostHog SDK
  // e.g., posthog.init('YOUR_PROJECT_KEY')
  return <>{children}</>
}
```

Then, wrap your app with it:

```typescript
export default function RootLayout({ children }) {
  return (
    <PHProvider>
      {children}
    </PHProvider>
  )
}
```

## Create error trigger UI

To trigger your test errors, create a simple interface:

```typescript
function ErrorGenerator() {
  return (
    <>
      {/* Button to trigger TypeError */}
      {/* Button to trigger ReferenceError */}
      {/* Button to trigger Null pointer error */}
      {/* Button to trigger Async error */}
    </>
  )
}
```

## Generate test errors

Run your app:

```bash
# Placeholder: start your Next.js app
```

In the browser:
- Click each button a few times to trigger errors
- Trigger multiple instances of the same type to create patterns for later debugging

You now have a sandbox of PostHog-captured test errors.

## Verify errors in PostHog

Check your PostHog dashboard to confirm that your test errors were captured:

1. Go to [PostHog errors](https://us.posthog.com/error_tracking).
2. You should see your test errors appear within a few minutes.
3. Click into an error to see the full stack trace.

<Checkpoint title="Lesson recap">

Before moving on, verify:

- App runs at localhost:3000
- Buttons trigger errors (check browser console)
- Errors appear in PostHog dashboard
- Stack traces show file names and line numbers

You now have four types of PostHog test errors:

- **Type errors**: Accessing properties on undefined
- **Reference errors**: Using undeclared variables
- **Null pointer errors**: Accessing properties on null
- **Async errors**: Unhandled promise rejections
